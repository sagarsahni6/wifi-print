# Technical SEO Audit: Printora (printora.app)

**Category Score**: 68 / 100  
**Weight**: 22%  
**Status**: Attention Required (1 Critical, 1 High, 1 Medium)

---

## 1. Executive Summary

A comprehensive technical audit was performed against all 26 static routes generated by the Next.js Turbopack engine on `printora.app`. The site achieves perfect HTTP 200 responses, pristine sitemap coverage, clean robots.txt directives, and lightning-fast TTFB. However, it suffers from a **critical sitewide absence of canonical URL tags**, leaving all 26 pages vulnerable to URL parameter duplicate indexing. Additionally, the application lacks standard HTTP security headers and exposes server fingerprinting.

---

## 2. Key Findings

### 2.1 Complete Absence of Canonical URL Tags
- **Severity**: Critical (P0)
- **Impact**: All 26 pages crawled lack `<link rel="canonical">`. When visitors arrive via marketing campaigns (`?utm_source=...`), referrals (`?ref=...`), or internal search strings, search engines may index duplicate variations and split PageRank equity.
- **Root Cause**: `src/app/layout.tsx` defines `metadataBase: new URL(siteConfig.url)` but omits `alternates: { canonical: './' }`, and no subpages define page-specific canonicals.
- **Evidence**:
  ```html
  <!-- Expected on https://printora.app/download/windows -->
  <link rel="canonical" href="https://printora.app/download/windows" />
  <!-- Actual: Tag is completely missing from <head> -->
  ```
- **Remediation**:
  In `src/app/layout.tsx`:
  ```typescript
  export const metadata: Metadata = {
    metadataBase: new URL(siteConfig.url),
    alternates: {
      canonical: "./",
    },
    // ...
  };
  ```

---

### 2.2 Missing HTTP Security & Hardening Headers
- **Severity**: High (P1)
- **Impact**: Server response exposes technology stack (`X-Powered-By: Next.js`) and fails to declare clickjacking protection, MIME sniffing protection, or referrer policies.
- **Evidence**:
  Current response headers:
  ```http
  X-Powered-By: Next.js
  Vary: rsc, next-router-state-tree, ...
  Content-Type: text/html; charset=utf-8
  ```
  Missing:
  - `X-Frame-Options: SAMEORIGIN`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: strict-origin-when-cross-origin`
  - `Permissions-Policy: camera=(self), microphone=(), geolocation=()`
- **Remediation**:
  In `next.config.ts`, disable the powered-by header and inject security headers:
  ```typescript
  const nextConfig: NextConfig = {
    poweredByHeader: false,
    async headers() {
      return [
        {
          source: "/(.*)",
          headers: [
            { key: "X-Frame-Options", value: "SAMEORIGIN" },
            { key: "X-Content-Type-Options", value: "nosniff" },
            { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" },
            { key: "Permissions-Policy", value: "camera=(self), microphone=(), geolocation=()" },
          ],
        },
      ];
    },
    // ...
  };
  ```

---

### 2.3 Internal Linking Asymmetry for `/qr-code-web-printing`
- **Severity**: Medium (P2)
- **Impact**: While 25 out of 26 pages enjoy 26 inbound internal links from sitewide navigation, `/qr-code-web-printing` has only **1 inbound link** because it was omitted from the footer link columns and navbar dropdowns.
- **Evidence**:
  Internal link crawler audit:
  ```text
  Route: /qr-code-web-printing | Inbound: 1 | Outbound: 25
  Route: /print-from-iphone-to-windows-printer | Inbound: 26 | Outbound: 25
  ```
- **Remediation**: Add a direct link to `/qr-code-web-printing` in the Solutions column of `src/components/Footer.tsx`.
